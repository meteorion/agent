# VPN 使用与排障手册

本文档面向全体员工，介绍公司 VPN 的安装、连接与常见故障处理。

## 1. 适用人群与前提

本手册适用于需要访问内网系统的正式员工与实习生。使用前请确认以下三项都已就绪：

- 已通过 IT 服务台开通 VPN 账号（工单类型：账号权限 → 远程接入）
- 电脑已安装公司统一的安全客户端，且客户端处于运行状态
- 手机已绑定动态口令（MFA），且手机时间与网络时间一致

外包人员与访客不在本手册范围内，请走「合作方接入」流程，该流程需要业务方负责人在工单中确认。

## 2. 安装客户端

请从内网软件中心下载最新客户端，不要使用第三方站点提供的安装包。第三方包可能被篡改，且不受安全策略保护。

### 2.1 Windows

下载 `CorpVPN-Setup.exe` 后以管理员身份运行，安装过程约 2 分钟。安装完成后需要重启一次电脑，否则虚拟网卡驱动不会生效，客户端会一直停在「初始化」状态。

安装完成后请校验版本，低于 5.2 的版本存在已知的重连缺陷：

```powershell
# 安装后校验版本（应不低于 5.2）
Get-Item "C:\Program Files\CorpVPN\vpncli.exe" | Select-Object VersionInfo
```

如果杀毒软件拦截了安装程序，请先把安装包路径加入白名单，再重新运行安装程序。不要为了绕过拦截而临时关闭杀毒软件，这会让后续的驱动加载也失去保护。

### 2.2 macOS

从软件中心下载 dmg 包，拖入「应用程序」后首次启动时，系统会提示"无法验证开发者"。此时需要前往「系统设置 → 隐私与安全性」，在页面下方找到被拦截的条目并点击「仍要打开」。

在「隐私与安全性 → 扩展」中，必须允许来自 CorpVPN 的系统扩展，否则客户端会一直显示「正在连接」并且没有任何错误提示。这是 macOS 上最常见的一个"看起来没坏、实际没工作"的情况。

### 2.3 移动端

移动端需要先安装 MDM 描述文件，安装后设备会受公司安全策略管理，包括强制锁屏密码与远程擦除。如果你不接受这项策略，请改用网页版内网门户，不要安装移动客户端。

## 3. 连接步骤

1. 打开客户端，服务器地址填写 `vpn.corp.example.com`
2. 用户名填写工号，密码为域账号密码
3. 输入动态口令
4. 连接成功后，托盘图标变为绿色

连接过程中不要切换网络（例如从 Wi-Fi 切到有线，或从公司网络切到手机热点），否则需要重新认证，部分客户端还会残留一条半开的隧道，表现为"显示已连接但打不开网页"。

如果公司网络启用了强制代理，需要先在客户端的高级设置里填写代理地址，否则握手阶段就会失败。代理地址请向所在办公区的 IT 现场支持索取。

## 4. 常见故障

### 4.1 提示「认证失败」

如果客户端提示认证失败，通常有三类原因：

- 密码已过期（公司域账号每 90 天强制更换一次）
- 动态口令与服务器时间偏差超过 30 秒
- 账号被锁定（连续输错 5 次会自动锁定 30 分钟）

处理顺序：先在自助门户重置密码；若仍失败，请校准手机时间后重试；最后再提交工单申请解锁。请不要反复重试，连续失败会延长锁定时长。

### 4.2 提示「无法建立隧道」

这通常是本地网络策略或代理导致的，与账号无关。请先按下表逐项排查：

| 现象 | 可能原因 | 处理方式 |
|---|---|---|
| 一直显示「正在连接」 | 本地防火墙拦截 UDP 443 | 临时关闭防火墙测试，确认后加白名单 |
| 连接后立刻断开 | 代理软件抢占路由表 | 退出所有代理与加速工具后重连 |
| 提示证书错误 | 系统时间不正确 | 开启自动同步时间后重试 |
| 提示「隧道已存在」 | 上次异常退出残留 | 重启客户端服务或重启电脑 |
| 提示「地址不可达」 | DNS 被本地网络覆盖 | 手动指定内网 DNS 后重试 |
| 提示「服务端拒绝」 | 账号在多个设备同时在线 | 退出其他设备上的客户端 |

排查时建议一次只改一项，改完立刻重试。同时改多项会让你无法判断是哪一项起了作用，下一次遇到同样问题时又得从头试一遍。

如果表格里的六项全部排除仍然失败，请检查本机是否安装了其他 VPN 或虚拟网卡软件（例如容器工具自带的虚拟网卡）。这类软件会抢占路由规则，导致公司客户端的流量走错出口。判断方法是在命令行执行 `route print`，看默认路由是否被指向了一个意料之外的虚拟网卡。

确认是路由冲突后，请卸载冲突软件或在其设置中关闭"接管全局流量"选项，然后重启公司客户端。不要用 `route delete` 手工删除路由，重启后它会自己回来，而且可能把你彻底断网。

### 4.3 连接成功但打不开内网系统

如果隧道已建立却访问不了内网地址，请检查 DNS 是否被本地网络覆盖。可以先访问 `http://intranet.corp.example.com` 测试。

若该地址可以打开，但具体业务系统打不开，说明问题在业务系统的权限配置，不是 VPN 问题，请改提「应用权限」类工单。这一步判断很关键，它能帮你省掉一轮无效的排查往返。

### 4.4 连接频繁掉线

高峰期（每天 9:00–10:00）接入网关会做连接数限流，出现规律性掉线属于正常现象，通常每隔十几分钟重连一次。

如果掉线没有规律，请打开客户端日志，查看断连前最后一条记录：

- 出现 `keepalive timeout`：本地网络不稳定，优先检查 Wi-Fi 信号
- 出现 `session limit reached`：你的账号在多台设备上同时登录，请退出一台
- 出现 `gateway reset`：服务端主动断连，通常是网关升级，等待 5 分钟后重连即可

## 5. 联系支持

以上步骤都无法解决时，请提交 IT 工单，工单类型选择「网络 → VPN」，并附上客户端日志（客户端菜单：帮助 → 导出日志）。工作时间内响应时间约为 2 小时，夜间与节假日按值班表响应。
